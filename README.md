# WarmSearch-T5 校园失物招领平台 配置库

## 项目简介
本项目基于开源项目 WarmSearch（https://github.com/lijinghailjh/WarmSearch）进行二次开发，在其失物招领业务基础上新增信用认领与保卫处贵重物品处置两条业务线。开源仓库仅公开了 Web 前端的部分页面，后端源码未开放，因此本项目后端按 SRS 与界面反推的字段从零实现，技术栈沿用开源基线。

## 目录结构
目录结构与《配置管理计划》中的配置库目录树一致：

- 01_系统需求：软件需求规格说明书、用例规约/、补充规约/、PC 前台界面原型、后台管理端界面原型、微信小程序界面原型、界面说明、需求追踪矩阵
- 02_系统设计与实施：概要设计/、详细设计/、数据模型/、SQL脚本/、源代码/、extern-baseline/
- 03_系统集成：系统集成构建计划/
- 04_系统测试：测试计划/、测试用例/、测试数据/、测试报告/
- 05_系统部署：部署包/、发布说明/、用户手册/、培训材料/
- 06_系统管理：软件开发计划、迭代计划/、配置管理计划、风险列表/、变更请求台账、基线清单、报告模板/
- 07_工具与标准：命名规范/、编程指南/、设计指南/、第三方组件清单/
- 08_基线归档：BL-1 至 BL-5 基线目录、基线清单、基线审批记录、配置审计记录/

说明：02 下的 `源代码/` 为目录树外的补充目录。原因是配置管理计划把源代码列为一类受控配置项（类型码 SRC），但目录树未给源代码预留位置，为满足“配置库包含所有代码”的要求而增设，已在《配置项登记表》中登记为 WS_SRC_R1.0。

## 配置标识
标识格式为 `<SYSTEM>[_<SUBSYSTEM>]_<A>_[R|A|B]<X>[.<Y>.<Z>][.BL<#>]`，SYSTEM 取 WS。已分配的标识见 `06_系统管理/配置项登记表.xlsx`，共 52 项，含类型码、版本、所属基线与存放位置。

## 分支策略
- main：受保护基线分支
- develop：集成工作区
- feature/credit：信用认领模块开发分支
- feature/security：保卫处贵重物品模块开发分支

## 基线标签
- WS_BL-1：初始阶段基线，计划 2026-09-27，实际 2026-09-27
- WS_BL-2：细化阶段基线，计划 2026-10-11，实际 2026-10-11
- WS_BL-3：构建阶段一基线，计划 2026-10-22，实际 2026-11-13（延期，原因见基线清单）
- WS_BL-4：构建阶段二基线，计划 2026-11-05，实际 2026-11-13（延期，原因见基线清单）
- WS_BL-5：交付阶段基线，计划 2026-11-19，尚未建立

每个基线目录下都有 `filelist.txt`，记录该基线全部文件的 SHA-256 与字节数，用于完整性校验。

## 校验方法
1. `git tag` 查看标签，`git show WS_BL-3` 查看标签指向的提交。
2. 进入任一基线目录，用 `Get-FileHash` 重新计算文件哈希，与 `filelist.txt` 比对。
3. 抽查文档封面，核对配置标识、版本、基线三项与登记表一致。
